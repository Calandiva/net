# GGYEMSSBBYOKK

기타 · 베이스 · 건반 · 우쿨렐레 코드 사전 + 크로매틱 튜너 + 메트로놈.
브라우저에서 돌고, 서버도 설치도 없다.

## 실행

```
python3 build.py     # src/*.js → index.html (의존성 없음, 1초)
open index.html      # 파일 더블클릭으로 실행. 서버 불필요
```

## 실행 환경 제약

- **서버 없음.** `index.html` 을 파일로 열거나 정적 호스팅만으로 완전히 동작한다.
- **빌드 단계가 하나 있다.** 브라우저는 `file://` 에서 ES 모듈을 CORS 로 막는다.
  소스는 진짜 모듈로 두고, `build.py` 가 IIFE 로 감싸 한 파일에 넣는다.
  번들러도 의존성도 없다(파이썬 표준 라이브러리만). `sy/build.py` 와 같은 물건이다.
- 마지막으로 본 탭만 `localStorage` 에 남는다. 막혀 있어도 그대로 돌아간다.
- **외부 이미지 · 폰트 · 라이브러리를 쓰지 않는다.** 악보 · 지판 · 건반은 전부 SVG 로
  코드가 그리고, 소리는 WebAudio 오실레이터로 만든다.

## 코딩 규약

유지보수 편의가 최우선이다.

- 매직 넘버 금지. 조정 가능한 값은 전부 `config.js` 로.
- **층을 섞지 않는다.** `theory/` 는 DOM 을 모르고, `render/` 는 화면 상태를 모른다.
  새 악기를 넣더라도 이 경계는 지킨다.
- 주석은 한국어로. "무엇을 하는지" 보다 **"왜 이렇게 했는지"** 를 적는다.
- **번들러가 단순하게 유지되도록 지키는 것들** (`build.py` 가 강제한다):
  - `import { a, b } from './x.js';` 형태만. default · 별칭 · 네임스페이스 import 금지.
  - `export [async] const/let/var/function/class 이름` 형태만. `export {}` 와 `export default` 금지.
  - 새 파일을 만들면 `build.py` 의 `MODULES` 에 의존성 순서로 추가한다.
  - 모듈 사이에 같은 이름을 export 하지 않는다(빌드가 이름 충돌을 잡아 준다).

## 음을 어떻게 담는가 — 여기가 제일 중요하다

음은 언제나 `{letter, alter, oct}` 다. 피치클래스(0~11) 하나로 들고 다니지 않는다.

```
letter : C=0 D=1 E=2 F=3 G=4 A=5 B=6   ← 오선 위 세로 자리를 정한다
alter  : -2 ~ +2                        ← ♭♭ ♭ ♮ ♯ ♯♯
oct    : 국제 표기 (가온다 = C4)
```

C♯ 과 D♭ 은 소리는 같아도 **악보에서 자리가 다르다.** 피치클래스만 들고 다니면 그 구별이
사라져서, C 의 ♭3 이 D♯ 으로 찍히는 사고가 난다. 도수에서 음을 만들 때는 반드시
`intervals.js` 의 `degToNote()` 를 쓴다 — 3도는 언제나 세 번째 글자가 된다.

그 대가로 `E7♯9` 의 ♯9 는 `F♯♯` 처럼 겹올림이 나온다. 이론상 맞는 철자이므로 그대로 두고,
화면에는 `voicing.js` 의 `alias` 가 `(= G)` 를 덧붙인다.

## 코드를 늘리려면

`theory/chords.js` 의 `CHORD_TYPES` 에 한 줄 넣고, 부르는 이름들을 `ALIAS` 에 적는다.

```js
m7b5: { sym: 'm7♭5', name: '하프 디미니시',
        degs: [d(1), d(3, -1), d(5, -1), d(7, -1)],
        hint: '마이너 2-5-1 의 첫 코드.' },
```

지판 운지 · 건반 보이싱 · 악보는 전부 `degs` 에서 자동으로 나온다. 따로 손댈 것이 없다.

## 악기를 늘리려면

`config.js` 의 `TUNINGS` 에 조율을, `INSTRUMENTS` 에 악기를 넣고 `TABS` 에 탭을 추가한다.
`kind` 가 `fret` 이면 `ui/inst-fret.js` 가 그대로 처리한다(우쿨렐레가 그렇게 붙어 있다).

## 음 개수와 생략 규칙

`theory/voicing.js` 가 정한다. 남기는 순서는 `intervals.js` 의 `keepRank()`:

| 순위 | 도수 | 왜 |
|---|---|---|
| 0 | 루트 | 코드의 이름 |
| 1 | 3음 (또는 sus 의 4·2음) | 밝은가 어두운가를 혼자 정한다 |
| 2 | ♭5 · ♯5 | 변형된 5도는 코드의 성격 자체다 |
| 3 | 7음 · 6음 | 7 코드인지 아닌지 |
| 4~ | 텐션 | 이름에 적힌 것(가장 높은 것 · 변형된 것)부터 |
| 9 | 완전5도 | 소리에 거의 영향이 없다. 제일 먼저 뺀다 |

13 코드에서 9 를 빼고 13 을 남기는 것이 이 규칙에서 나온다.
`bandOmit`(루트 · 완전5도)은 "밴드에서는 빼도 된다" 는 별개의 표시다.

## 지판 운지를 어떻게 찾는가

`theory/fretboard.js` 의 `findShapes(tuningKey, plan, opts)`.
4프렛 창을 밀면서 줄마다 (뮤트 · 개방현 · 창 안의 해당 음) 후보를 만들고 전수로 조합한다.
`opts` 로 모양(`SHAPE_STYLES`) · 프렛 범위 · 전위 허용 여부를 건다.

**손으로 못 잡는 모양을 걸러 내는 것이 이 파일의 핵심이다.** 음만 맞으면 되는 조합은
수백 가지가 나오는데 대부분 사람 손으로는 안 된다. 손가락은 1<2<3<4 순으로 프렛이
커지는 쪽에 놓여야 하고, 그 순서를 어기면 손이 꼬인다. `fingering()` 이 두 가지를 본다.

1. **바레보다 얇은 줄에 바레보다 낮은 프렛이 있으면 안 된다.** 바레 손가락 뒤로 다른
   손가락이 돌아 들어갈 수 없다. `x02210`(Am)을 "바레 2손가락" 으로 세지 않는 이유가 이것이다.
2. **같은 프렛을 여러 손가락으로 나눠 짚어야 하는데 그 사이 줄에 더 높은 프렛이 있으면 안 된다.**
   반대로 사이가 더 낮으면 괜찮다 — `320003`(G)의 3프렛 두 개 사이에 2프렛이 있는 것은
   실제로 다들 잡는 모양이다.

이 두 규칙 덕분에 `C=x32010`, `F=133211`, `G=320003`, `Am=x02210`, `Bm7=x20202`,
`Dm9=x53555`, `Cm11=8 8 8 8 8 10` 처럼 실제로 치는 운지가 1순위로 나온다.

점수는 낮은 자리 · 적은 손가락 · 많이 울리는 줄 · 안 건너뛰는 것을 좋아한다. 개방현 덤은
낮은 자리에서만 준다 — 12프렛에서 개방현을 섞는 건 초보가 쓸 운지가 아니다.

**재진입 조율 주의.** 우쿨렐레 하이G 는 4번 줄이 제일 높다. 그래서 "제일 낮게 울리는 음" 은
줄 순서가 아니라 실제 음높이로 찾아야 하고, "베이스가 루트" 라는 규칙 자체가 성립하지 않는다
(`TUNINGS[...].reentrant` 가 그 표시다). 이걸 안 지키면 `C=0003`, `F=2010` 이 안 나온다.

## 악보를 어떻게 그리는가

`render/staff.js`. 자료 꼴은 이렇다.

```js
{ clef: 'treble' | 'bass' | 'perc',
  time: [4, 4],
  percMap: { HH: { pos, head, up }, ... },   // clef 가 'perc' 일 때만
  measures: [ [ev, ev, ...], ... ] }

ev = { p: 'C4' | ['E4','G4'] | null(쉼표),
       d: 1|2|4|8|16, dot: true,
       text: '아',                   // 오선 아래 (가사 · 손가락 번호 · 박 세기)
       label: 'Em' }                 // 오선 위 (코드 이름 · 도수)
```

- 세로 자리는 `letter`·`oct` 로 정한다(`stepToY`). 그래서 E♭ 과 D♯ 이 다른 줄에 앉는다.
- **화음은 기둥이 하나다.** 가운데 줄에서 가장 먼 음이 아래면 기둥은 위로, 위면 아래로.
  타악보는 예외다 — 손은 위, 발은 아래로 따로 간다.
- 이어진 8·16분음표는 박 단위로 묶어 빔을 그린다. 방향마다 따로 묶는다.
- **높은음자리표는 나선을 계산해서 그린다.** 손으로 찍은 곡선이 아니라서 크기를 바꿔도
  안 망가지고, 나선의 중심이 정확히 둘째 줄(솔)에 앉는다.
- **기타 악보는 실제 소리보다 한 옥타브 높게 적는 것이 관례다.**
  `INSTRUMENTS[...].octaveShift` 가 그 값이고, 화면에도 그렇게 적었다고 밝힌다.

## 튜너

`audio/pitch.js` 에 알고리즘 여섯 가지가 같은 모양으로 들어 있다:
`fn(x: Float32Array, sr) -> { hz, clarity } | null`. `PITCH_ALGOS` 가 화면 목록이다.

새 알고리즘을 넣으려면 함수 하나 쓰고 `PITCH_ALGOS` 에 한 줄 넣으면 된다.

알아 둘 것

- **기본값이 NSDF 인 이유.** 자기상관의 최댓값을 그냥 고르면 주기 T 의 배수에도 봉우리가
  서서 한 옥타브 아래를 집는다. NSDF 는 정규화한 뒤 **가장 높은 봉우리의 88% 를 넘는 "첫"
  봉우리**를 고른다. 그 첫 봉우리가 진짜 주기다.
- **AMDF 의 문턱은 비율이 아니라 구간으로 잡는다.** 깨끗한 소리는 최솟값이 0 에 붙어 버려서
  "최솟값의 몇 배" 로 재면 아무것도 못 고른다. `mv + (dmax-mv)*0.15` 를 쓴다.
- **HPS 는 순음에서 보정이 필요하다.** 배음이 없으면 곱이 기음의 1/2·1/3 자리에 선다.
  원래 스펙트럼에 에너지가 실제로 있는지 확인하고 없으면 배수 자리로 올라간다.
  그리고 포물선 보간은 **로그 크기**로 해야 몇 센트 안으로 들어온다.
- **절반으로 솎아 낸 뒤(≈24kHz) 잰다.** 사람이 튜닝하는 음역에는 충분하고 계산이 네 배 줄어든다.
  `fftSize` 8192 는 5현 베이스 B0(30.9Hz)의 주기를 담기 위한 값이다.
- **`clarityMin` 은 0.72.** 배음이 기음보다 센 악기는 또렷함이 1.0 까지 안 올라간다.

`audio/tuner.js` 가 마이크를 열고 위 함수를 부른다. 여기서 겪은 것 두 가지:

- **requestAnimationFrame 을 쓰지 않는다.** 화면이 안 그려지는 상황(탭이 뒤로 가거나
  렌더링이 멈춘 창)에서는 rAF 가 아예 안 불려서 튜너가 조용히 얼어붙는다. 어차피
  `TUNER.periodMs` 마다만 재면 되므로 타이머로 돈다.
- **파형이 통째로 0 이면 다시 붙인다.** 브라우저에 따라, 컨텍스트가 깨어나기 전이나 스트림이
  흐르기 전에 만든 `MediaStreamAudioSourceNode` 가 영영 무음이 되는 일이 있다. 트랙은
  살아 있는데 0.5초 넘게 정확히 0 이면 소스와 분석기를 다시 만든다(최대 세 번).
  조용히 죽어 있는 튜너가 제일 나쁜 고장이다.

## 메트로놈

`setInterval` 로 소리를 내면 타이머 지터가 그대로 들린다. 25ms 마다 깨어나 100ms 앞까지의
클릭을 **오디오 시계에 미리 예약**해 둔다. 화면 램프만 `setTimeout` 으로 따라 붙는다
(눈은 조금 늦어도 된다). 자동 증속과 쉬는 마디는 마디가 넘어가는 순간에만 계산한다.
